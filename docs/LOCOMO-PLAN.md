# LoCoMo benchmark: pre-registered plan

Written and committed before any LoCoMo arm was run (no A0 query, no model call). Do not edit this file after results exist; a
change goes in a dated amendment section at the end. Every figure in section 9 was computed offline from the dataset file and the
segmenter only (no index, no model); none of them is a result.

Status of every number that this benchmark produces: EXPLORATORY. This plan sets no pass or fail threshold and uses no
outcome words (HOLDS, DID NOT HOLD and so on); it reports estimates with intervals.

## 1. Purpose

A second public long-memory benchmark beside LongMemEval-S: LoCoMo (snap-research/locomo, `data/locomo10.json`, ACL 2024,
CC BY-NC 4.0). It compares the flat hybrid baseline A0 with the tree arms A1 (tree fused with the flat list by RRF) and
A1-tree-only, as already defined in `docs/EXPERIMENT.md` and `evalkit/arms.py`. The arm code is not changed.

recall query, as in LongMemEval).

## 3. Unit of evaluation and memory content

- **One tenant per conversation** (10 conversations, file order index 0 to 9, tenant name `lcmo<i>`, so ES indices `lc-lcmo<i>-*`).
  A question is only ever asked against its own conversation's tenant.
- **Turn text.** role = `speaker` name. Content = `text`, then ` [image: <blip_caption>]` appended when the turn has a caption
  (909 of the 2,361 resolved evidence turns have one, so dropping captions would remove evidence content). The first turn of each
  session is prefixed `[<session_N_date_time>] ` so dates exist in memory; the date is therefore present only in the first leaf of a
  session. No evidence turn has empty text (counted offline), so the segmenter's dropping of empty turns cannot remove a gold turn.
- **Leaves.** The existing segmenter at the harness leaf cap (`Constants().leaf_cap` = 1536 tokens), exactly as `EvalTenant.ingest`
  does. The turn to leaf map comes from the same segmenter run with each turn's index carried in `Turn.ts` (a pure label: the time
  gap rule fires only on gaps over 1,800, and consecutive indices differ by 1). The harness asserts, at ingest and before any arm
  runs, that (a) every segmented leaf's rendered text equals the text the tenant stored for the leaf at that position, and (b) for
  every evidence turn, that turn's text occurs in the stored text of its mapped leaf. A failed assertion stops the run.
- **Session** = LoCoMo session `Dn` (n = session number). A leaf belongs to exactly one session (the segmenter cuts at session
  boundaries).

## 4. Questions and gold

- Categories 1, 2, 3, 4 only. Category 5 (adversarial) is excluded (no evidence). Categories are labelled by number: the LoCoMo
  repository's evaluation code does not name them, and no name is asserted here.
- `qid` = `<sample_id>#<index of the item in the conversation's qa list>`.
- **Evidence parsing rule.** For every string in `evidence`, take all matches of the regular expression `D:?(\d+):0*(\d+)` and
  normalise each to `D<n>:<m>` (so `D8:6; D9:17` gives two ids, `D:11:26` gives `D11:26`, `D30:05` gives `D30:5`; a bare `D` gives
  none). Keep only ids that name a turn that exists in that conversation. A question is **eligible** when at least one id resolves;
  ids that do not resolve are dropped (a partly resolvable question stays in, scored against its resolvable gold). A question with
  no resolvable id is excluded and counted.
- **Gold leaves** = the leaves containing any resolved evidence turn. **Gold sessions** = the sessions `Dn` of the resolved ids.

## 5. Arms, subset, order

- **A0**: flat hybrid (BM25 over text, title and entities, plus e5 dense, client-side RRF, window 50; the `strong` field set, the
  default of S2 and S3). No model call. Run on **all eligible questions**.
- **A1** and **A1-tree-only**: one tree recall per question, A1-tree-only is that recall's tree list, A1 is RRF(tree list, A0 list).
  Run on a **seeded stratified subset** of 100 questions, with A0 on the same subset for the paired comparison. The paired A0
  list is the one computed at recall time; it must equal the all-questions A0 row of the same question (checked and reported).
- **SHUFFLED-SUMMARIES** negative control (`arms.PermutedView`) on the first 30 subset questions, if the cap allows. It is not
  pre-registered as returning about zero: with pools of 25 to 59 leaves it may well retrieve gold by chance, and the number is
  reported as measured.
- **Subset rule.** Allocation of 100 across categories proportional to eligible counts, largest remainder, ties to the lower
  category (computed from the section 9 counts: category 1: 18, 2: 21, 3: 6, 4: 55). Within a category, eligible questions are
  ordered by `sha256("16096:locomo:" + qid)` ascending and the first n_c are taken. The subset order is the same hash order across
  the chosen 100, so the first 30 (SHUFFLED) are not one category or one conversation by construction.
- **Optional secondary batch B2 (decided now, run only if the conditions hold).** After B1 (the subset above) completes, if B1
  used at most 2,500 model calls and the time box has room, run A1 and A1-tree-only (and A0, paired) on a second batch of up to 300
  further eligible questions not in B1, chosen by the same rule on the remaining questions, SHUFFLED not repeated, subject to the
  call cap (B2 starts only if spent plus 1.15 times B1's mean calls per question times the batch size is at most 8,500). B2 is
  reported separately, and B1 plus B2 pooled is labelled as such. B1 alone is the primary result. If B2 is not run, the report says
  so.

## 6. Metrics

All per arm, per question, then averaged over questions. Lists are scored as returned: a tree-only list shorter than k is not
padded. A failed recall scores 0 and is counted, never dropped.

| Metric | Definition |
|---|---|
| gold-leaf recall@5, @10 | gold leaves in the first k leaves of the arm's ranked leaf list, divided by the number of gold leaves |
| gold-session recall@5 (primary session metric) | gold sessions among the first 5 distinct sessions of the leaf list, divided by gold sessions; @10 reported beside it |
| MRR@10 (leaf level) | 1 / rank of the first gold leaf within the first 10 leaves, else 0 |
| all-gold@10 (leaf level) | questions with at least 2 gold leaves only: 1 if every gold leaf is in the first 10 leaves, else 0. A session-level version (at least 2 gold sessions, first 10 distinct sessions) is reported beside it |
| chance reference | for gold-leaf recall@k, the exact expectation under a uniformly random ranking of the question's pool, min(k, N) / N for a pool of N leaves, averaged over the same questions |

Every recall@k table carries the pool size (leaves per conversation: section 9), because a top-10 list covers a large share of a
pool this small.

## 7. Statistics

- Intervals: percentile 95% clustered bootstrap of the mean (`evalkit.stats.clustered_bootstrap`), 10,000 resamples, seed 16096.
- **Primary cluster = conversation x session-of-first-evidence**, where "first evidence" is the first id of the question's evidence
  list that resolves. Rationale: questions about the same session share evidence and are not independent. **Sensitivity cluster =
  conversation** (10 clusters), reported beside it for every interval; with so few clusters it is coarse and is shown to
  bound how much the primary interval depends on the cluster choice.
- Paired differences, on the subset questions: A1 minus A0, A1-tree-only minus A0, and A1 minus A1-tree-only, for each metric, with
  the same clustered bootstrap on the per-question paired differences.
- Per-category breakdown: means and paired differences per category number. Category 3 has about 6 subset questions: its intervals
  are reported but are not interpretable and the report says so.
- A0 on all eligible questions is reported with the same intervals and also per category and per conversation.

## 8. Budget, run controls, reproducibility

- Model calls only through `evalkit.claude_cli.CappedPort` over the Claude CLI (`--model sonnet`), the models the CLI reports are
  recorded. One durable counter, one `calls.jsonl`, one journal for the whole run, hard cap **9,000** calls (build plus recall,
  every retry attempt is charged). The OpenRouter route is not used.
- Up to 6 questions at a time; within a recall the calls are serial (`workers=1`), as in S2. Concurrency is adaptive with ceiling 6
  (it halves on a throttle), and the ceiling and any change are logged.
- Logged per question: wall seconds around the tree recall (includes waiting for a concurrency slot), holder calls, and the
  summed latency of the call log rows of that recall where they can be attributed; per call: task, tokens, latency.
- Runs on t2-dev under `~/lc-locomo/` only, against the Elasticsearch container `lc-es-16441` (loopback port 19741). Tenants are
  created with `registry_doc_only=True`, so no other tenant's registry is touched, and the tenant names are checked against the
  existing index names first.
- Code is synced with `git archive` of the committed HEAD; the run stamps that commit. Results: `run/` holds `STATE.json`,
  `calls.jsonl`, `done.jsonl`; `evalkit/locomo_report.py` regenerates the tables from the run directory alone.
- Time box 3.5 hours. If the planned work does not finish, the results file states how many of the planned questions completed.

## 10. Known limits stated in advance

- Pools of 25 to 59 leaves: A0 already sees a large share of each pool, the tree has only 1 to 2 levels, and recall@10 has a high
  chance level. Results do not transfer to the 4,000 to 78,000 leaf pools of the LongMemEval work.
- Retrieval only: no answer generation, no end-to-end QA accuracy.
- Model: Sonnet through the Claude CLI at whatever version the CLI reports; not the model of S3 or S6-H1.
- The session date is attached to the first leaf of a session only.
